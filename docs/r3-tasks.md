# R3 — задачи

Рабочий файл. **Агент читает его перед началом задачи и обновляет статус в конце.**
Требования — в [r3-spec.md](./r3-spec.md).

Порядок работы — как в R1 и R2: одна задача за сессию, проверки перед
коммитом, запись в журнал решений о том, что оказалось не так, как
предполагалось.

Задачи идут в порядке зависимостей. Первые три — становой хребет релиза:
пока глоссарий не станет входом генерации, остальное косметика.

---

### R3-1 · Оригиналы документов остаются
**Статус:** todo · **Зависит от:** — · **Требования:** S1–S6, I4

Первая, потому что всё остальное на ней стоит: пока оригинал удаляется через
15 минут, сборку глоссария и генерацию скрипта нельзя разнести на два шага.

Отмена F1 из R1: файл живёт в хранилище, пока владелец не удалит его сам.
Несколько документов на проект. Кнопка удаления у каждого. Текст под формой
загрузки переписывается: сейчас он обещает удаление, а будет обещать
хранение. F2 не трогаем — извлечённый текст по-прежнему не сохраняется.

Повторная загрузка того же файла (сверка по `sha256`, поле уже есть) не
запускает вторую генерацию молча, а спрашивает.

**Приёмка:** загруженный вчера документ доступен сегодня; удаление уносит
файл из Blob, а не только строку; удаление проекта по-прежнему уносит всё.

### R3-2 · Сборка глоссария отдельным шагом
**Статус:** todo · **Зависит от:** R3-1 · **Требования:** N1–N2, N2а, I1–I3

Новый вызов модели, своя схема ответа, своя запись в `generations` с видом
`glossary`. Все документы проекта — в один вызов. Новый шаг воронки между
`document_uploaded` и `script_generated`.

Глоссарий переезжает на странице проекта под документы, выше файлов и звука.

Сборка идёт больше минуты: предупреждение перед уходом со страницы плюс
видимый статус из `generations` при возвращении. Механизм устаревания
(`STALE_AFTER_MS`, `failStaleGenerations`) уже есть — переиспользовать.

**Приёмка:** уйти со страницы во время сборки и вернуться — видно, что
сборка шла; файл не просят загрузить заново.

### R3-3 · Глоссарий — вход генерации скрипта
**Статус:** todo · **Зависит от:** R3-2 · **Требования:** N3–N7

Ради этого релиз и затеян. Выверенный глоссарий уходит в промт за тем же
ограждением, что документ (Б7). Модель обязана использовать эквиваленты;
`verified` и `from-practice` не переписываются никогда.

Поле `glossary` уходит из схемы ответа генерации скрипта или меняет смысл:
возвращаются только новые кандидаты, они падают в глоссарий как `suggested`
и ничего не затирают.

**Приёмка:** переписать эквивалент руками, сгенерировать скрипт — в скрипте
стоит ваш вариант, а не модельный; перегенерировать — правка на месте.

### R3-4 · Три слоя глоссария
**Статус:** todo · **Зависит от:** R3-3 · **Требования:** T1–T10

Связь с проектом перестаёт быть обязательной — **это сокращение схемы,
то самое, на котором Payload вешает тесты.** Снимать `NOT NULL` руками,
проверять `\d glossary_terms`.

Порядок перекрытия: проектный → личный → общеприкладной. Подстановка при
сборке, а не при показе. Перенос в более общий слой — только руками.
Общеприкладной слой наполняет владелец сервиса; пользователи в него не пишут.

**Приёмка:** один исходный термин с разными эквивалентами в двух проектах
живёт спокойно; удаление проекта не трогает личный слой; выгрузка
показывает, откуда пришёл действующий эквивалент.

### R3-5 · Команда проекта правит глоссарий
**Статус:** todo · **Зависит от:** R3-4 · **Требования:** K1–K5, L1

Совместный доступ, заложенный на R4, приходит сюда. У проекта появляется
состав переводчиков — кто идёт в кабину. Правит тот, кто связан учётной
записью; названный текстом входит в состав, но не правит (правило W6).

Личный слой остаётся закрытым: в проект из него приходят копии, не ссылки.

**Приёмка:** коллега из состава открывает глоссарий чужого проекта и правит
его; человек не из состава получает 404, а не пустую страницу.

### R3-6 · Участники события и произношение имён
**Статус:** todo · **Зависит от:** R3-5 · **Требования:** L2–L5

Состав участников у проекта: имя, организация, произношение свободным
текстом. Загрузка списка файлом в любом виде, разбирает модель, человек
выверяет.

Третьи лица без согласия: только текст, никакой публичной страницы,
уезжают вместе с проектом. Ограничение W4 из R2 остаётся.

**Приёмка:** список из PDF организатора превращается в строки с именами;
удаление проекта уносит их.

### R3-7 · Печатная форма глоссария
**Статус:** todo · **Зависит от:** R3-4 · **Требования:** I7–I8

Страница для печати: крупно, в колонки, без интерфейса. Неподтверждённые
термины помечены, как в выгрузке. Google Docs и Sheets не трогаем.

**Приёмка:** печать из браузера даёт читаемый в кабине лист без кнопок
и навигации.

### R3-8 · Мелкие починки интерфейса
**Статус:** todo · **Зависит от:** — · **Требования:** I5–I6

Независима от прочего, можно брать в любой момент.

Числовые поля (`Number` в `document-upload.tsx`): поле хранит строку, а не
число, очищается досуха, ведущий ноль не прилипает к набранной цифре.
Сейчас `globalThis.Number("")` даёт 0, и ноль остаётся в поле.

SSML убирается из списка файлов проекта: это промежуточный формат.

**Приёмка:** очистить поле «Спикеров», набрать 5 — в поле 5, не 05.
