# R3 — спецификация: всё начинается с глоссария

Цель релиза: развернуть порядок работы так, как он устроен у переводчика.
Сегодня глоссарий — побочный продукт генерации скрипта. Должен быть её
основанием.

Основание — живой отзыв практикующего переводчика (19 сентября 2026).
Дословно: работа начинается с загрузки презентации и составления
глоссария; глоссарий уточняют между собой те, кто идёт на событие вместе;
и уже из выверенного глоссария растёт тренировочный скрипт, а из скрипта —
звук.

## Главная мысль

Глоссарий — это то, ради чего переводчик готовится. Скрипт и звук —
тренажёр вокруг глоссария, а не наоборот.

Сегодня всё устроено обратным образом, и это не оттенок, а поломка: термины
приходят прицепом к скрипту (`script-generation.ts`, поле `glossary` в схеме
ответа), в промт генерации глоссарий не попадает вовсе (`prompt.ts` знает
слово «glossary» только как имя поля ответа), а в воронке шаг
`glossary_exported` стоит после `audio_generated`. Значит, **правка терминов
руками сегодня ни на что не влияет**: скрипт уже сгенерирован, а
перегенерация выбросит правки и снова спросит термины у модели.

Отсюда следствия, которые нельзя срезать при реализации:

- выверенный человеком термин **никогда** не переписывается моделью;
- скрипт генерируется из глоссария, а не рядом с ним;
- один и тот же термин в разных проектах переводится по-разному, и это
  норма, а не конфликт, который надо разрешить.

## Принятые решения

| Решение | Значение | Почему |
|---|---|---|
| Глоссарий — отдельный шаг | Извлечение терминов своим вызовом модели, до скрипта | Иначе выверка ни на что не влияет: скрипт уже написан |
| Три слоя глоссария | Общеприкладной → личный → проектный, ближний перекрывает дальний | Память между событиями нужна, но суд и корпоратив требуют разных эквивалентов одного термина. Общий справочник избавляет от перевода одного и того же дважды |
| Глоссарий проекта правит команда | Совместный доступ приходит в R3, а не в R4 | Выверка «между собой» — то, ради чего релиз и затеян. Без неё остальное половинчато |
| Перенос в общий слой — только руками | Автоматического «запоминания» нет | Автоматика затащит в память случайный эквивалент одного мероприятия, и вычищать его будет некому |
| Оригиналы больше не удаляются сами | Удаление — явное действие владельца | Переводчики их не удаляют, а для многих организаций материалы публичны. Пересмотр F1 из R1 |
| Печатная форма — своя, не Google Sheets | Страница для печати в приложении | Лист в кабину нужен сегодня, а интеграция с Google — это OAuth, права и чужое хранилище |
| Разбор списка участников — моделью | Принимаем файл в любом виде | Списки от организаторов не бывают аккуратными таблицами |
| Форма обратной связи | Не в этом релизе | Обсуждается отдельно, см. `docs/open-items.md` |

## Требования

### N — новый порядок работы

| ID | Требование |
|---|---|
| N1 | Порядок: проект → документы → глоссарий собран → глоссарий выверен → скрипт → аудио. Шаги воронки отражают этот порядок |
| N2 | Извлечение терминов — отдельный вызов модели со своей схемой ответа и своей записью в `generations` (новый вид `glossary`) |
| N2а | Все документы проекта уходят в один вызов: термин, встреченный в двух презентациях, не должен раздваиваться, а модель должна видеть событие целиком |
| N3 | Скрипт генерируется отдельной кнопкой и только когда в проекте есть глоссарий |
| N4 | Выверенный глоссарий уходит в промт генерации скрипта как материал, отделённый тем же ограждением, что и документ (Б7 аудита) |
| N5 | Модель обязана использовать эквиваленты из глоссария. Термины со статусом «подтверждён» и «из практики» она не переписывает |
| N6 | Генерация скрипта не перезаписывает глоссарий. Новые термины, встреченные в скрипте, добавляются кандидатами со статусом «предложен моделью» |
| N7 | Перегенерация скрипта не трогает ни один выверенный термин |

### T — три слоя глоссария

Слои по возрастанию частности: **общеприкладной** (справочник сервиса) →
**личный** (память переводчика) → **проектный** (этот заказчик, это
событие). Ближний слой перекрывает дальний, дальние при этом не меняются
и остаются видны.

| ID | Требование |
|---|---|
| T1 | Термин принадлежит одному из трёх слоёв: общеприкладному, личному слою переводчика или проекту. Связь с проектом перестаёт быть обязательной |
| T2 | При сборке глоссария проекта термин, совпавший по исходной форме, подставляется из ближайшего слоя, в котором он есть, и виден как пришедший оттуда |
| T3 | Порядок перекрытия: проектный сильнее личного, личный сильнее общеприкладного. Перекрытый эквивалент остаётся виден рядом с действующим |
| T4 | Разные эквиваленты одного исходного термина в разных проектах — нормальное состояние. Ни предупреждения, ни разрешения конфликта не требуется |
| T5 | Перенос термина в более общий слой — явное действие человека, никогда не автоматическое |
| T6 | Сопоставление между слоями — по нормализованной исходной форме: регистр и краевые пробелы не различают термины |
| T7 | Удаление проекта не затрагивает личный и общеприкладной слои |
| T8 | Выгрузка отдаёт действующий для проекта эквивалент и показывает, из какого слоя он пришёл |
| T9 | Общеприкладной слой наполняет владелец сервиса. Пользователи в него не пишут: иначе первый же случайный эквивалент уедет всем |
| T10 | Автоподстановка из общеприкладного слоя происходит при сборке глоссария, а не при каждом показе: подставленный термин дальше живёт как проектный и правится как проектный |

### K — выверка командой

| ID | Требование |
|---|---|
| K1 | Глоссарий проекта доступен команде проекта на правку, а не только владельцу. Это переносит в R3 совместный доступ, заложенный на R4 |
| K2 | Правит тот, кто связан учётной записью. Названный текстом в состав входит, но не правит — то же правило, что у записей о работе (W6) |
| K3 | Авторство варианта видно: человек по имени, модель — подписью «модель». Уже заложено в данных (D3), требуется в интерфейсе |
| K4 | Личный слой глоссария принадлежит одному переводчику и команде не открывается: в проект из него приходят копии, а не ссылки |
| K5 | Правка коллеги не затирает чужую молча. Минимум — последняя запись видна с именем автора и временем |

### L — люди события

| ID | Требование |
|---|---|
| L1 | У проекта есть состав переводчиков: кто идёт в кабину. Сейчас состав существует только у записи о прошедшем событии |
| L2 | У проекта есть состав участников: имя, организация и **произношение имени** |
| L3 | Произношение — свободный текст, как переводчику удобно читать в кабине: своя транскрипция, IPA, что угодно. Это обязательная часть карточки, а не примечание: неанглоязычное имя на слух не угадывается, и выяснять его надо до события |
| L4 | Список участников загружается файлом в любом виде — программа PDF, таблица, письмо организатора. Разбирает модель, человек выверяет результат |
| L5 | Участники — третьи лица без согласия на хранение. Только текст, никакой публичной страницы, удаляются вместе с проектом. Ограничение W4 из R2 остаётся в силе |

### S — исходные документы (пересмотр F1–F3 из R1)

| ID | Требование |
|---|---|
| S1 | На проект загружается несколько документов, а не один |
| S2 | Оригинал не удаляется автоматически. Удаление — явное действие владельца в любой момент |
| S3 | В интерфейсе видно, что оригинал хранится, и рядом — как его удалить |
| S4 | Напоминание об удалении оригиналов приходит через неделю после события, рядом с уже существующим напоминанием о разборе. Оно предлагает, а не удаляет |
| S5 | Если оригинал удалён, перегенерация из него невозможна, и сказано об этом заранее |
| S6 | F2 остаётся без изменений: извлечённый текст по-прежнему нигде не сохраняется |

### B — расходы (дополнение к R1)

| ID | Требование |
|---|---|
| B4 | Сборка глоссария и разбор списка участников — платные вызовы модели. Каждый пишет свою запись в `usage_events` со своим видом |
| B5 | Оба идут в тот же месячный лимит, что скрипт и аудио. Отдельного потолка у глоссария нет |

### I — интерфейс и починки

| ID | Требование |
|---|---|
| I1 | Глоссарий на странице проекта стоит сразу под документами — выше файлов, скрипта и звука |
| I2 | Глоссарий открывается и правится на самой странице проекта. Отдельная страница остаётся запасным путём |
| I3 | Долгая генерация не теряется при уходе со страницы: перед уходом спрашивают, а вернувшись человек видит по записи в `generations`, что сборка идёт, — и не загружает файл второй раз |
| I4 | Повторная загрузка того же файла не запускает вторую генерацию молча |
| I5 | Числовое поле очищается досуха. Сегодня стирание значения оставляет в поле 0, и набранная следом пятёрка читается как «05». Диапазоны значений не меняются |
| I6 | SSML не показывается в файлах проекта: это промежуточный формат, а не результат |
| I7 | Печатная форма глоссария в приложении: страница для печати, крупным шрифтом, без интерфейса — лист наклеивают в кабине. Печатается весь глоссарий; неподтверждённые термины помечены, как в выгрузке |
| I8 | Выгрузка CSV и XLSX для InterpretBank сохраняется как есть |

## О номере релиза

В `r1-spec.md` под R3 были записаны оплата и тарифы. Живой отзыв переводчика
их обогнал: платить за инструмент, который просит глоссарий после звука,
никто не станет. Тарифы сдвигаются, номер занимает этот релиз.

## Существующие данные

Глоссарии заведённых проектов остаются как есть: по новой модели они —
обычные проектные термины, и ничего с ними делать не надо. В личный слой
из них ничего не переносится автоматически (T5). Разовый экран «забрать
старое в память» не строится: захочет — перенесёт руками.

Общеприкладной слой стартует пустым. Его первое наполнение — словари
DE/FR/TR, которые в `docs/open-items.md` ждут владельца: это ровно тот
справочник, о котором речь в T9, и теперь у него есть куда лечь.

## Что не делается в R3

- Интеграция с Google Docs и Sheets. Печатная форма закрывает потребность
  без OAuth и чужого хранилища.
- Форма обратной связи в приложении — отдельное решение владельца.
- Сторона заказчика, отзыв сессий (Б5), английский интерфейс (T14).

## Что меняется в ранее принятых решениях

**F1 из R1 отменяется частично.** «Оригинал удаляется не позднее 15 минут
после успешной генерации» заменяется на «оригинал хранится, пока владелец
не удалит его сам». Причина — полевая: переводчики оригиналы не удаляют, а
для многих организаций исходные материалы публичны. F3 меняется следом:
в интерфейсе загрузки говорится о хранении и о том, как удалить.

Это разворот решения, принятого ради приватности, и цену надо назвать
вслух: документы заказчиков теперь лежат в хранилище неопределённо долго.
Удержано два ограничения — извлечённый текст не сохраняется (F2) и
удаление проекта уносит файлы из Blob (F4). Третьим ограничением
становится S4: напоминание не даёт забыть о накопленном.

**Побочный выигрыш.** Сегодня генерация идёт одним запросом именно потому,
что оригинал нельзя пережить между запросами. Хранение снимает это: сборка
глоссария и генерация скрипта расходятся на два шага без единого костыля.
