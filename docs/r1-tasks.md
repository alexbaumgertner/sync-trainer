# R1 — задачи

Рабочий файл. **Агент читает его перед началом задачи и обновляет статус в конце.**
Требования — в [r1-spec.md](./r1-spec.md).

## Как с этим работать

Одна задача — одна сессия агента. Не давайте агенту «сделай R1»: на пятинедельной
задаче без разбиения любая модель и любой инструмент уплывут. Порядок действий:

1. Взять первую задачу со статусом `todo`, у которой все зависимости `done`.
2. Прочитать её критерии приёмки и требования, на которые она ссылается.
3. Сделать, прогнать `npm run build`, `npx eslint src --max-warnings=0`, `npm run smoke`.
4. Закоммитить.
5. Поставить статус `done` и записать, что оказалось не так, как предполагалось.

Статусы: `todo` · `doing` · `done` · `cut`

### T01 · Postgres, схема, слой доступа
**Статус:** done · **Зависит от:** — · **Требования:** D1, D3, D4

- Neon Postgres через маркетплейс Vercel, переменные подставляются автоматически
- Схема из спецификации, миграции в репозитории
- Слой доступа, в котором проверка владения проектом выполняется централизованно

**Приёмка:** запрос к чужому проекту возвращает «не найдено», а не чужие данные.
Тест на это существует.

**Сделано.** Payload 3.89 на Postgres, 9 коллекций, права в `src/lib/access.ts`.
Проверки: `tests/integration/access.test.ts` — 9 тестов через Local API,
`tests/e2e/access.spec.ts` — 6 сквозных. Начальная миграция применяется
на чистой базе. Админка на `/admin`, REST Payload уведён на `/payload-api`,
чтобы не перекрыть наши `/api/tts` и `/api/usage`.

### T02 · Вход по одноразовому коду и приглашения
**Статус:** done · **Зависит от:** T01 · **Требования:** A1–A7

- `APP_PASSWORD` удаляется, вместе с ним старый экран входа
- Отправка писем через Resend, отправитель на своём домене
- Ограничители в базе, не в памяти процесса
- **Персональные приглашения:** запись в Invitations, письмо со ссылкой,
  содержащей одноразовый токен с сроком годности
- Стратегия входа по коду поверх коллекции users; локальная стратегия
  остаётся для админки

**Приёмка:** неизвестный адрес получает тот же ответ, что известный. Шестая попытка
кода отклоняется. Четвёртое письмо за 15 минут не отправляется. Ссылка приглашения
срабатывает один раз, повторный переход отклоняется. Без приглашения войти нельзя.

**Сделано.** `APP_PASSWORD` удалён. Вход в два шага: адрес → код из письма.
Сессия — подписанная кука, её же читает стратегия Payload `otp-cookie`,
поэтому система входа одна на приложение и админку. Приглашения выписываются
хуком коллекции: работает и из админки, и из `npm run invite`. Ограничители
частоты в базе, не в памяти процесса. 18 интеграционных тестов и 9 сквозных.

### T03 · Расходы по пользователям
**Статус:** done · **Зависит от:** T01, T02 · **Требования:** B1–B3, D2

- Перенос накопленного счётчика из Blob в `usage_events` одноразовым скриптом
- Третье условие в `budgetBlock()`: месячный лимит на пользователя
- Отображение расхода на проекте, в профиле и глобально

**Приёмка:** суммы после миграции совпадают с теми, что были в Blob. Пользователь
с исчерпанным личным лимитом получает 402, остальные работают.

**Сделано.** Счётчик переехал из JSON в Blob в таблицу `usage_events`.
Лимитов теперь три: общий за всё время, общий за месяц и личный месячный
у пользователя. Перенос — `npm run migrate:usage`, суммы сверены и сошлись.
Обычный пользователь видит свой расход и остаток по сервису, оборот целиком —
только администратор. 8 тестов на привязку, лимиты и видимость.

### T05 · Загрузка документа и удаление оригинала
**Статус:** done · **Зависит от:** T04 · **Требования:** F1–F4

- PDF, DOCX, PPTX до 25 МБ
- PDF уходит в Gemini напрямую; DOCX и PPTX раскладываются в текст библиотеками
- Оригинал удаляется, остаются метаданные и `purged_at`
- Извлечённый текст нигде не сохраняется

**Приёмка:** после генерации оригинала нет ни в Blob, ни в базе. Извлечённый текст
не встречается ни в одной таблице. При ошибке обработки оригинал тоже удалён.

**Сделано.** PDF, DOCX, PPTX до 25 МБ. DOCX через mammoth, PPTX разбирается
своим кодом (zip с XML слайдов), PDF не разбирается вовсе — только счёт страниц,
текст читает модель. Оригинал удаляется и при успехе, и при ошибке. Сквозной
тест ищет фразу из документа во всех текстовых колонках базы; проверено, что
он действительно падает, если текст сохранить.

### T07 · Генерация скрипта
**Статус:** done · **Зависит от:** T05, T06 · **Требования:** G1, G3, G4

- Структурированный ответ по схеме: `{title, speakers[], segments[], ssml, glossary[]}`

**Приёмка:** десять генераций подряд разбираются без единой ошибки парсинга.

**Сделано.** Gemini со структурированным ответом по схеме. Генерация идёт в том же

с пустыми репликами, с половинчатыми терминами, с не-JSON.

**Не проверено:** настоящий вызов Gemini. Ключа в тестах нет, вызов стоит денег.

### T08 · Синтез аудио

## Журнал решений

Сюда — то, что выяснилось в работе и противоречит спецификации.
Спецификация правится следом, иначе она устареет к третьей неделе.

| Дата | Задача | Что оказалось не так |
|---|---|---|
| 13.09 | T01 | Payload CLI грузит конфиг как CommonJS, а lexical — ESM с top-level await. Пакет переведён в ESM (`"type": "module"`) — штатная конфигурация для Payload 3 |
| 13.09 | T01 | REST Payload по умолчанию садится на `/api` и перекрыл бы `/api/tts`. Уведён на `/payload-api` через `routes.api` |
| 13.09 | T01 | Хук владельца безусловно перезаписывал `owner` из сессии: ломалось серверное создание, администратор не мог завести проект на другого. Теперь сессия форсирует владельца только для обычного пользователя |
| 13.09 | T01 | Анонимный запрос Payload отклоняет с Forbidden, а не возвращает пустой список. Тест приведён к фактическому поведению — оно строже |
| 13.09 | T01 | `@types/node` был 20-й версии при Node 24 в runtime; Vitest 5 требует 22+. Типы приведены к реальности |
| 13.09 | A5 | Статический список адресов заменён персональными приглашениями по прямой просьбе. Спецификация исправлена |
| 13.09 | D5 | Резервное копирование добавлено требованием: у Neon на бесплатном плане окно всего 6 часов, полагаться на провайдера нельзя. Задача T16 |
| 13.09 | T02 | Конфигурация Payload грузится вне Next, поэтому `server-only` в цепочке импортов ломает CLI. Криптография сессии вынесена в чистый `session.ts`, а из `email.ts` пометка снята: этот модуль вызывает хук коллекции |
| 13.09 | T02 | `createInvitation` сам выставлял `tokenHash`, хук из-за этого пропускал выписку и письмо не отправлял никто. Токен теперь всегда рождается в хуке, код передаёт свой через `context` — оба пути одинаковы |
| 13.09 | T02 | Приглашение принимается не только ссылкой, но и кодом на тот же адрес: ссылка легко теряется в почте, а требовать вторую было бы издевательством |
| 13.09 | T02 | Для неприглашённых адресов запись кода всё равно создаётся — она служит счётчиком частоты, — но `delivered` остаётся false, и войти по угаданному коду нельзя |
| 13.09 | A5 | Локальная стратегия Payload требует пароль, поэтому приглашённому ставится случайный, которого не знает никто. Вход по нему не предусмотрен |
| 13.09 | T03 | Журнал в старом формате обрезан до 200 записей, а итоги полные. Чтобы суммы после переноса сошлись, скрипт добавляет балансирующую запись на разницу — иначе часть расходов просто исчезла бы |
| 13.09 | T03 | Обычному пользователю отдаётся не оборот сервиса, а только остаток по общим лимитам: кнопку гасить надо, а знать чужие суммы незачем |
| 13.09 | T03 | Пометка `server-only` снята с модулей, которые нужны и маршрутам, и скриптам обслуживания (`otp`, `invitations`, `usage`, `payload`, `email`). Осталась там, где модуль правда может попасть в клиентский код: `auth`, `google-tts`, `silence` |
| 13.09 | T04 | Блокирующий баг, найденный тестом: у внешних ключей `SET NULL`, а колонка `project_id` объявлена `NOT NULL` — проект с любым артефактом не удалялся вовсе. Каскад перенесён в `beforeDelete`, до удаления самого проекта |
| 13.09 | T04 | Payload не удаляет связанные записи каскадом сам: без хука остались бы висячие артефакты, термины и разборы |
| 13.09 | T04 | Подсказки под полями формы лежали внутри `<label>` и попадали в доступное имя поля — диктор читал бы «Название Как вы сами будете его искать», а поиск по метке цеплял соседние поля. Вынесены и связаны через `aria-describedby` |
| 13.09 | T04 | Корень ведёт в список проектов; прежняя студия с ручной вставкой SSML переехала на `/studio` и живёт там до T07–T08 |
| 13.09 | T05 | Тело запроса к функции Vercel ограничено 4.5 МБ, а документ разрешён до 25 МБ. Через сервер такой файл не пройдёт, поэтому в проде браузер кладёт его в Blob напрямую по временному токену, а сервер получает только адрес. Локально предела нет и файл идёт через сервер, не попадая в хранилище вовсе |
| 13.09 | T05 | PPTX разбирается своим кодом: это zip с XML слайдов, текст в элементах `a:t`. Отдельная библиотека ради двадцати строк добавила бы зависимость, которую пришлось бы поддерживать |
| 13.09 | T05 | PDF намеренно не разбираем — его читает сама модель. Свой парсер испортил бы таблицы и колонки, а именно в них в таких документах и лежат цифры |
| 13.09 | T05 | Проверено, что тест на конфиденциальность способен упасть: с временно сохранённым текстом он нашёл утечку и назвал колонку. Тест, который не может провалиться, хуже отсутствующего |
| 13.09 | T06 | Список языков сначала сортировался по алфавиту, и это породило миграцию, которая пересоздаёт enum ради перестановки значений. Порядок задан явно: он попадает в схему базы, и алфавит здесь не нужен никому |
| 13.09 | T06 | `payload migrate:create` зависает на интерактивном вопросе, когда изменений в схеме нет. В npm-скрипт добавлен `--forceAcceptWarning` |
| 13.09 | T06 | Подписи пресетов дублировались в трёх местах: коллекции, форме и `lib/projects`. Теперь единственный источник — реестр |
