# R1 — спецификация

Машиночитаемая версия. Человеческая, с обоснованиями и оценками:
https://claude.ai/code/artifact/c4ab54a8-b580-49b2-9c23-150a14d54694

Цель релиза: от одного общего пароля и вставленного вручную SSML —
к учётным записям, проектам и генерации из документа.

## Принятые решения

| Решение | Значение |
|---|---|
| Языки | Расширяется **язык исходной речи**: EN, DE, FR, TR. Интерфейс — русский и английский |
| Отзыв о событии | Разбор для следующей подготовки, а не дневник и не оценка материала |
| Документы | Оригинал удаляется после обработки. Перегенерация из него невозможна — принято осознанно |

## Требования

### A — вход по одноразовому коду

| ID | Требование |
|---|---|
| A1 | Код 6 цифр из криптостойкого источника, в базе только хеш, срок истечения, счётчик попыток, отметка использования |
| A2 | Не более 5 попыток на код; после исчерпания код аннулируется |
| A3 | Не более 3 писем на адрес за 15 минут и 20 с IP за час. Счётчики в базе, не в памяти процесса |
| A4 | Ответ на запрос кода не различает существующего и нового пользователя ни текстом, ни временем |
| A5 | Доступ по персональному приглашению: администратор заводит запись в Invitations, приглашённому уходит письмо со ссылкой, содержащей одноразовый токен. Ссылка одноразовая и с сроком годности. Открытой регистрации нет |
| A6 | Выход завершает текущую сессию. «Выйти везде» в R1 нет |
| A8 | Паролей нет вовсе: локальная стратегия Payload отключена, вход только по коду. Запасной путь при отказе почты — через базу и `AUTH_SECRET`, без сетевого маршрута |
| A7 | Письма через внешний сервис, отправитель на своём домене с SPF и DKIM |

### D — данные

| ID | Требование |
|---|---|
| D1 | Проверка владения проектом в слое доступа к данным, а не в каждом обработчике |
| D2 | Счётчик расходов из Blob переносится в `usage_events` одноразовым скриптом без потери сумм |
| D3 | Термины глоссария хранят происхождение с самого начала, даже без интерфейса подтверждения |
| D4 | Схема в проде меняется только миграциями из репозитория; `push` включён лишь вне продакшена |
| D5 | Резервное копирование не полагается на провайдера: независимая выгрузка по расписанию |

### F — документы

| ID | Требование |
|---|---|
| F1 | Оригинал удаляется не позднее 15 минут после успешной генерации и немедленно при ошибке |
| F2 | Извлечённый текст не сохраняется, живёт только в памяти во время обработки |
| F3 | В интерфейсе загрузки сказано, что оригинал будет удалён и перегенерация невозможна |
| F4 | Удаление проекта удаляет его артефакты из Blob, а не только строки в базе |

### G — генерация

| ID | Требование |
|---|---|
| G1 | Ответ модели запрашивается по схеме, не свободным текстом |
| G2 | SSML проверяется до синтеза: парсер, байты кусков, допустимые теги |
| G3 | Скрипт и аудио — два отдельных шага с отдельными кнопками ($0.04 против $0.47) |
| G4 | Скрипт можно отредактировать вручную перед синтезом |
| G5 | Материал помечается как синтетический в интерфейсе и в скачиваемом файле |
| G6 | Голоса из живого списка Google, отфильтрованные по языку проекта и поддержке SSML |

### U — интерфейс

| ID | Требование |
|---|---|
| U1 | Карточка проекта показывает все файлы с датой, размером и ссылкой на скачивание |
| U2 | Глоссарий выгружается в CSV и в формат InterpretBank |
| U3 | Генерация в фоне: страницу можно закрыть и вернуться, статус виден в списке |
| U4 | Интерфейс на русском и английском, переключатель в профиле — **кандидат на R1.5** |

### E — разбор после события

| ID | Требование |
|---|---|
| E1 | Отметка «прозвучало на событии» у каждого термина глоссария |
| E2 | Поле для недостающих терминов, каждый попадает в глоссарий со статусом «из практики» |
| E3 | Короткие вопросы: темп, что было труднее всего, совпадение с реальностью. Поле в схеме — `hardest`, не `went_well`: «всё прошло хорошо» не подсказывает, что генерировать дальше |
| E4 | Разборы прошлых проектов подмешиваются в промт следующей генерации |
| E5 | Напоминание о разборе через день после события — **кандидат на R1.5** |

### B — расходы и лимиты

| ID | Требование |
|---|---|
| B1 | Каждая запись о расходе привязана к пользователю и проекту |
| B2 | Лимит на пользователя в месяц, третьим условием в существующем `budgetBlock()` |
| B3 | Стоимость видна на проекте, в профиле за месяц и глобально для владельца |

## В R1 не входит

Запись перевода и оценка (R2), совместная работа и ревью коллегой (R4),
оплата и тарифы (R3), профиль компетентности (после R2), мобильное приложение.

## Схема данных

```
users              id, email, created_at, invited_at, ui_locale, role
                   (без hash/salt: паролей нет — A8)
otp_codes          email, code_hash, expires_at, attempts, consumed_at   [T02]
invitations        id, email, token_hash, expires_at, accepted_at,
                   accepted_by, invited_by, note
projects           id, user_id, title, event_name, event_starts_on,
                   event_location, source_lang, target_lang,
                   style_preset, status, created_at
documents          id, project_id, filename, mime, bytes, sha256,
                   pages, extracted_chars, purged_at
generations        id, project_id, kind, params_json, model,
                   status, chars, cost_usd, created_at
artifacts          id, project_id, generation_id, kind,
                   blob_path, bytes, created_at
glossary_terms     id, project_id, source_term, target_term, note,
                   status, proposed_by, verified_by, verified_at,
                   occurred_at_event
debriefs           id, project_id, held_on, hardest, missing_terms,
                   surprises, actual_pace, created_at
usage_events       id, user_id, project_id, kind, chars,
                   cost_usd, created_at
```

## Что переиспользуется без изменений

- `src/lib/ssml.ts` — разбор, нарезка под лимит 5000 байт, план синтеза
- `src/lib/silence.ts` — генерация MP3-тишины для text-режима
- `src/lib/google-tts.ts` — клиент, ретраи, параллельный синтез, склейка
- `src/lib/voices.ts` — каталог голосов, тарифы, выбор формата
- `src/lib/budget.ts` — проверка лимита, расширяется третьим условием
- `src/lib/auth.ts` — подпись сессионной куки, `guard()`; пароль заменяется на код
