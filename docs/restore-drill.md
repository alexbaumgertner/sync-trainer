# Восстановление базы: учение и боевой порядок

Файл лежит в репозитории рядом со `scripts/restore.mjs`, а не в заметках:
искать его будут в тот день, когда всё плохо, и найтись он должен там же,
где код, который описывает.

**Проведите это учением, пока данных нет.** Непроверенная копия — надежда,
а не копия. Час сейчас стоит дешевле, чем первая попытка вслепую потом.

---

## Сначала — нужно ли вообще восстановление

Три вопроса по порядку, каждый следующий дороже предыдущего.

**Ошибка сделана меньше шести часов назад?** У Neon на бесплатном плане есть
восстановление на момент времени с окном шесть часов. Оно точнее и быстрее
нашей суточной копии: восстанавливает состояние на минуту, а не на три часа
ночи. Делается в консоли Neon, кодом трогать ничего не нужно. Это первый
ответ на «удалил не то».

**Пострадал один проект или один человек?** Возможно, проще достать нужное
из копии руками, чем откатывать всё. Копия — обычный JSON внутри шифра;
`npm run backup:verify` покажет, что в ней лежит, ничего не меняя.

**Потеряна база целиком или повреждена незаметно и давно?** Вот тогда —
восстановление ниже.

---

## Что нужно иметь под рукой

- **`BACKUP_KEY`** — тот, что вы завели `openssl rand -base64 32`. Без него
  копия нечитаема, и никто, включая меня, восстановить её не сможет.
  **Проверьте прямо сейчас, что он есть не только в менеджере паролей
  на рабочем ноутбуке.** Копия, ключ от которой лежит в том же месте, что
  и всё остальное, защищает ровно от тех бед, которые не случаются.
- **Сама копия** — вложение из ночного письма (имя кончается на `.json.enc`)
  либо путь в хранилище вида `backups/2026-09-16-03-00-00.json.enc`.
- **Доступ к консоли Neon** — там заводится база, куда восстанавливать.

---

## Учение (безопасно, боевого не касается)

### Шаг 1. Убедиться, что копия читается вашим ключом

Ничего не меняет, базы не касается. Если этот шаг не прошёл — дальше идти
незачем, и хорошо, что вы узнали об этом на учении.

```bash
BACKUP_KEY='<ваш ключ>' npm run backup:verify -- ~/Downloads/<копия>.json.enc
```

Ожидаем: дату копии, узел-источник, перечень таблиц со строками. Сверьте
глазами, что таблицы на месте все — проверка в тестах ловит поломки кода,
но не то, что копия стала неполной из-за недосмотра в схеме.

### Шаг 2. Завести пустую базу для учения

В консоли Neon у проекта `neon-claret-kettle` создайте ветку и назовите
её так, чтобы через месяц было понятно: `drill-2026-09`. Ветку от **main**,
но нам нужна пустая схема, поэтому проще создать новый *проект* Neon —
ветка приезжает с данными родителя и скроет ошибку, если восстановление
на самом деле ничего не запишет.

Возьмите строку подключения этой базы. Дальше она везде `$TARGET`.

### Шаг 3. Создать схему миграциями

Порядок важен: схему создают миграции из репозитория, а не копия.

```bash
NODE_ENV=production DATABASE_URI="$TARGET" npx payload migrate
```

`NODE_ENV=production` здесь не украшение. Без него Payload сначала
синхронизирует схему через `push`, и учение проверит что угодно, только
не миграции — на этом мы уже обжигались, и запись об этом есть в журнале
решений. С этой переменной `push` выключен, и если миграции неполны,
вы узнаете об этом сейчас, а не в аварии.

Ожидаем: перечень применённых миграций, без ошибок.

### Шаг 4. Восстановить

```bash
BACKUP_KEY='<ваш ключ>' DATABASE_URI="$TARGET" \
  npm run restore -- ~/Downloads/<копия>.json.enc
```

Скрипт покажет, откуда копия, сколько строк и **в какую базу** будет писать,
и потребует ввести слово `восстановить`. Прочитайте строку с базой назначения
глазами: это единственная защита от восстановления поверх той самой базы,
которую спасают.

Ожидаем: перечень таблиц с числом строк и «последовательностей перенесено».

### Шаг 5. Убедиться, что восстановленное работает

Числа в отчёте — не доказательство. Поднимите приложение на этой базе:

```bash
DATABASE_URI="$TARGET" AUTH_SECRET='<любой>' npm run dev
```

(`npm run dev` по дороге синхронизирует схему через `push` — для проверки
это не помеха, миграции вы уже проверили на шаге 3 с выключенным `push`.)

И проверьте руками:

- список проектов открывается и в нём те проекты, что были;
- у проекта видны файлы, и скачивание отдаёт содержимое;
- запись о работе на месте, участник в ней — с тем же статусом;
- вход: `npm run session -- ваша@почта` выдаёт куку, и с ней вы внутри.

Последний пункт важнее прочих: восстановленная база без возможности войти
бесполезна ровно так же, как отсутствующая.

### Шаг 6. Прибраться и записать

Удалите учебный проект Neon — он ест бесплатную квоту. Запишите здесь же,
внизу файла: дату учения, с какой копии, что пошло не так и сколько заняло.
Через полгода это единственный источник сведений о том, работает ли у вас
восстановление.

## Боевой порядок

Отличается двумя вещами: спешкой и тем, что в конце надо переключить
продакшен.

1. **Не восстанавливайте поверх боевой базы.** Даже если кажется, что терять
   нечего. Разворачивайте в новую базу — пока старая цела, у вас две попытки,
   а не одна.
2. Шаги 1–5 учения, без изменений.
3. **Переключите приложение:** в Vercel замените `DATABASE_URL` и
   `DATABASE_URL_UNPOOLED` на строки восстановленной базы, окружение
   Production. `POSTGRES_URL` от интеграции Neon трогать не нужно: порядок
   в `src/lib/database-url.ts` — `DATABASE_URI` → `DATABASE_URL` →
   `POSTGRES_URL`, и первый найденный побеждает. Выбранный узел приложение
   пишет в лог при каждом старте (`[db] подключение из …`) — по этой строке
   и убедитесь, что переключение сработало.

   Переменные вступают в силу только после передеплоя: нажмите Redeploy,
   иначе приложение продолжит работать со старой базой, и вы решите,
   что восстановление не удалось.
4. Проверьте по списку из шага 5, но на боевом адресе.
5. Старую базу **не удаляйте** минимум неделю.

### Чего вы потеряете

Копия снимается в 3:00. Всё, что люди сделали между тремя часами и аварией,
в копии не окажется. Об этом придётся сказать пользователям — и лучше
сказать самому, чем дать заметить.

Окно можно сузить, если данные станут дороже: Neon на платном плане даёт
восстановление на момент времени за неделю. Сегодня это лишние деньги,
при первых платящих — уже нет.
