# R2 — спецификация: профиль и записи о работе

Цель релиза: от личного тренажёра — к профессиональному следу. Переводчик
ведёт записи о проведённых конференциях, коллеги их подтверждают, из этого
складывается карточка, которую можно показать.

Основание — полевой опрос переводчиков (15 сентября 2026): просили личный
профиль и отзыв о проведённых конференциях с организатором, командой,
спикерами и тем, как всё прошло.

## Принятые решения

| Решение | Значение | Почему |
|---|---|---|
| Разбор и запись — разные сущности | `debriefs` остаётся приватным, появляется `engagements` | Разбор честен, пока его никто не видит. «Сбился на третьей панели» не должно попасть туда, где его прочтёт коллега |
| Запись не требует проекта | Связь с `projects` необязательная | У переводчика годы конференций до тренажёра. Требуй проект — и профиль в первый день пуст, заполнять его незачем |
| Видимость записи | Владелец и названные участники команды | Ответ на полевой вопрос. Уровни «заказчику» и «по ссылке» закладываются в модель, но не строятся |
| Публичной анонимной страницы нет | Карточка видна только вошедшим | Решение владельца продукта. Снимает вопросы модерации и согласия третьих лиц на этом этапе |
| Коллеги | Имя текстом; совпал адрес с учётной записью — связываем; нет — можно пригласить | Работает с первого дня и дорастает до пула само |
| Сторона заказчика | Не строится в R2 | Двусторонняя площадка тяжелее инструмента, а выбирать организатору пока не из кого |

## Что делает запись достоверной

Главная мысль релиза, и от неё зависит всё остальное.

Утверждение «я переводил с Ивановой на форуме X» само по себе ничего не
стоит: его может написать кто угодно. Оно становится ценным, когда **Иванова
его подтвердила**. Подтверждение — не украшение и не «социальная функция»,
а единственное, что отличает профиль от резюме, в котором можно написать
что угодно.

Отсюда следствия, которые нельзя срезать при реализации:

- подтверждение даёт **только** сама учётная запись коллеги, не владелец записи;
- неподтверждённое упоминание видно как неподтверждённое, а не молча как факт;
- коллега может **оспорить** запись, а не только подтвердить: иначе подтверждение
  ничего не гарантирует;
- подтверждение — это ещё и согласие на упоминание. Отзовёт — имя уходит.

## Требования

### P — профиль

| ID | Требование |
|---|---|
| P1 | Имя, языковые пары (направленные: EN→RU отдельно от RU→EN), город, специализации, членство в объединениях, свободный текст о себе |
| P2 | Профиль видят только вошедшие пользователи. Анонимной страницы нет |
| P3 | Владелец выбирает, что показывать: каждое поле профиля скрывается отдельно |
| P4 | В профиле видны записи о работе, доступные смотрящему, и счётчики: сколько событий, с какого года |
| P5 | Модель видимости расширяемая: добавление уровня «заказчику» не требует переписывать проверки доступа |

### W — записи о работе

| ID | Требование |
|---|---|
| W1 | Запись: событие, организатор, дата, место, режим (синхрон/последовательный), рабочие языки, как прошло |
| W2 | Связь с проектом необязательная. Запись можно завести о конференции, которой в тренажёре не было |
| W3 | Команда: имена участников. Совпал адрес с учётной записью — связываем, нет — остаётся текстом |
| W4 | Спикеры: имя и организация. Только текст: их согласия у нас нет и не будет |
| W5 | «Как прошло» — оценка и свободный текст. Это не разбор: сюда пишут то, что не стыдно показать команде |
| W6 | Запись видна владельцу и связанным участникам команды. Несвязанным (текстовым) — нет |
| W7 | Участник может дополнить запись своим комментарием, не правя чужой текст |

### C — подтверждение и приглашение

| ID | Требование |
|---|---|
| C1 | Связанный участник получает письмо и подтверждает или оспаривает участие |
| C2 | Неподтверждённое участие помечено как неподтверждённое везде, где показано |
| C3 | Оспоренное участие скрывается из профиля владельца записи до разбирательства |
| C4 | Участника без учётной записи можно пригласить по почте; приглашение использует существующий механизм (A5) |
| C5 | Отзыв подтверждения убирает имя из записи. Подтверждение есть согласие на упоминание |
| C6 | Напоминание о неподтверждённом участии — один раз, по правилам E5 |

### D — данные (дополнение к R1)

| ID | Требование |
|---|---|
| D6 | Имена спикеров и несвязанных коллег — данные третьих лиц. Не показываются никому, кроме владельца записи и подтверждённой команды |
| D7 | Удаление учётной записи не удаляет чужие записи, но убирает из них имя и связь |

## Схема данных

```
users            + displayName, city, bio, memberships, visibility_json
                   (профиль живёт на пользователе: отдельная таблица
                    на связь один-к-одному ничего не даёт)

language_pairs     id, user_id, source, target, level
specializations    id, user_id, name

engagements        id, owner_id, project_id NULL, title, organizer,
                   held_on, location, mode, source_lang, target_lang,
                   went_how (1..5), went_text, visibility, created_at

engagement_members id, engagement_id, user_id NULL, name, email NULL,
                   booth, status (invited|confirmed|disputed|withdrawn),
                   confirmed_at, note

engagement_speakers id, engagement_id, name, organization, note
```

## В R2 не входит

Сторона заказчика и оплата (R3), публичные страницы, поиск по коллегам
и подбор в кабину (R4), взаимное ревью глоссария (R4), английский интерфейс
(остаётся кандидатом, T14).

## Порядок работ

| № | Задача | Зависит от |
|---|---|---|
| 1 | Профиль: поля, страница, видимость по полям (P1–P3) | — |
| 2 | Записи о работе: сущность, форма, список (W1–W2, W4–W5) | 1 |
| 3 | Команда: имена, связывание по адресу (W3, W6) | 2 |
| 4 | Подтверждение и оспаривание (C1–C3, C5) | 3 |
| 5 | Приглашение коллеги из записи (C4) | 3 |
| 6 | Профиль показывает записи и счётчики (P4) | 2, 4 |
| 7 | Напоминание о неподтверждённом (C6) | 4 |

Порядок не случаен: до задачи 4 записи — это личные заметки, и ценность
у них личная. Подтверждение превращает их в профессиональный след, ради
которого релиз и затевается.
